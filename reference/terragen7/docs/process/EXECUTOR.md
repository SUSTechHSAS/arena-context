# 执行者守则（EXECUTOR）

你是实现者。规格已经由架构师写好，你的工作是**忠实、诚实、可验证地**把一张任务卡变成代码。

## 1. 隔离规则（必须遵守）

- 只读写 `/home/kibi/Work/TerraGen7/` 目录。**禁止**读取 `/home/kibi/Work/` 下其他任何目录、`~/.claude` 下的记忆或其他项目文件，也不要回忆/照搬你见过的其他地形生成器实现。
- 允许查阅：本仓库、Rust 标准库文档、`~/.cargo/registry` 中**允许依赖**（§08.1）的源码与文档、通用科学知识与论文中的公式。
- 不从网络复制代码。

## 2. 开始前

1. 阅读：本文件、任务卡、卡片“必读”列出的规格章节、依赖 crate 的公开 API（`cargo doc` 或源码）。
2. 从最新 `main` 创建分支 `task/Txx-<slug>`（若已在 worktree 中，确认所在分支即可）。
3. 不要编辑 `docs/tasks/STATUS.md`（由审核者维护，避免并行任务冲突）。确认环境变量或 `.cargo/config.toml` 使用共享构建目录（§08.1），不要在 worktree 内另建 `target/`。

## 3. 实现规则

1. **接口**：任务卡与规格中给出的公开签名必须实现且保持一致。确需改动时：先用最小改动实现，报告中写 ICR（§5），由审核者决定。
2. **物理与数值诚实**：
   - 不得用球面公式（经纬度、`sin(lat)` 科里奥利、常数 g）代替 `Body` 提供的环面量；所有度量相关计算使用 §01.3 的行度量。
   - 不得硬编码“看起来对”的输出、跳过物理步骤或用噪声冒充过程结果。
   - 单位一律 SI（地质时间用年），在注释中写明单位。
3. **确定性**：遵守 §08.4 的四条规则；有并行的模块必须加 `assert_deterministic` 测试。
4. **测试**：
   - 实现卡片列出的全部验收测试；可以增加，不能删减。
   - **不得为了通过而放宽阈值**。达不到时如实报告实测数值与分析。
   - 快速测试用 `test` 预设（全工作区 `cargo test` < 3 min）；长测试标 `#[ignore]` 并写明运行命令。
5. **代码组织**：单文件 ≤ 800 行；模块内聚；公共项有文档注释；不引入未允许的依赖；无 `unsafe`。
6. **性能**：用 `--release` 测量卡片要求的耗时/内存并写入报告。
7. **范围**：只做本卡内容，不“顺手”重构其他 crate。发现他处 bug：记录在报告“发现的问题”节。

## 4. 完成前

1. `scripts/check.sh` 全部通过（fmt、clippy -D warnings、快速测试）。
2. 运行卡片指定的慢速测试（如有）。
3. 生成审查图到 `artifacts/Txx/`（卡片“审查图”一节列出的每一张），并**自己看一遍**：有 NaN 空洞、条纹、接缝、对称性破坏等异常时先排查。
4. 写报告 `docs/reports/Txx.md`（模板见 §6）。
5. 提交：`Txx: <简述>`。

## 5. BLOCKED 与 ICR

- **BLOCKED**：规格自相矛盾、数值上不可行、或需要重大设计选择而规格未给出时，停止编码，在报告中写“BLOCKED”节：问题、你的分析、2–3 个选项、推荐项。提交已完成部分，并在最终总结中明确写出 BLOCKED。
- **小决策**（规格未写但影响局部）：自行决定，写入报告“决策记录”节。
- **ICR**：接口变更申请：动机、原签名、新签名、影响的模块。

## 6. 报告模板（`docs/reports/Txx.md`）

```markdown
# Txx <任务名> — 执行报告

## 第 1 轮（日期，模型名）
### 完成内容
- 文件与模块清单（每项一句话）
### 验收测试
| 测试 | 结果 | 实测值 | 阈值 |
### 性能
| 项目 | 预设 | 耗时 | 峰值内存 | 预算 |
### 审查图
- artifacts/Txx/xxx.png — 说明图中应看到什么
### 决策记录
### 偏差与未完成项
### 发现的问题（他处）
### ICR（如有）
### BLOCKED（如有）
```

修订轮在末尾追加 `## 第 N 轮`，逐条回应审核意见编号。
