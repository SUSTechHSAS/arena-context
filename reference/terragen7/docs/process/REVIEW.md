# 审核规程（REVIEW）

审核者：Claude Opus 5.5。目标是尽早发现**物理错误、数值错误、确定性破坏与不诚实的测试**，而不仅是代码风格。

## 1. 流程

1. **准备**：切到任务分支/worktree，阅读 `docs/reports/Txx.md` 与任务卡。
2. **复现**：运行 `scripts/check.sh`、卡片要求的慢速测试、`scripts/preview.sh Txx`；核对报告中的数值能复现（差异 > 5% 视为 MAJOR）。
3. **规格符合性**：逐条对照卡片“验收”与引用的规格条目，列出未满足项。
4. **物理与数值**（重点）：
   - 单位与量纲；符号约定（σ 方向、f 符号 `−2Ωρ'`、法向朝外、东-北-上右手系）。
   - 度量因子：是否在所有差分、面积、距离中使用 ρ(σ)；有无把 (u,σ) 当作均匀平面。
   - 重力：是否处处用 `Body::g`；有无残留 9.81 常量或球面公式。
   - 守恒：质量/能量/体积/泥沙的守恒测试是否真实计算了收支。
   - 稳定性与收敛：时间步、CFL、隐式格式的正确性；网格加密收敛。
   - 边界：周期 wrap 在负索引、跨界插值处是否正确；窗口 halo 的 Dirichlet 处理。
5. **确定性**：§08.4 四条规则；并行模块的 `assert_deterministic` 测试确实跑了 1 与 N 线程。
6. **测试质量**：测试是否真的能失败（必要时临时注入错误验证）；阈值是否被放宽；是否只测了平凡情况。
7. **代码质量**：结构、重复、错误处理、文档注释、依赖、`unsafe`、文件长度。
8. **性能**：与卡片及 §00.6 预算对比。
9. **图像**：逐张查看审查图：NaN 空洞、沿网格轴的条纹、接缝、块状伪影、不应有的对称/不对称、数值范围异常、与物理预期（如内侧自遮挡、雨影、上下半环季节相反）是否一致。

## 2. 问题分级

| 级别 | 含义 | 处理 |
|---|---|---|
| BLOCKER | 物理/数值错误、确定性破坏、测试造假或缺失关键验收 | 必须修复 |
| MAJOR | 规格不符、性能超预算 > 50%、明显伪影、接口偏离未申请 | 必须修复 |
| MINOR | 可读性、局部低效、测试覆盖不足 | 应修复 |
| NIT | 风格建议 | 可选 |

## 3. 结论

- **ACCEPT**：无 BLOCKER/MAJOR。合并：rebase 到 main → 重跑 check → `git merge --no-ff` → 更新 STATUS 为 MERGED。
- **REVISE**：列出编号问题，发回执行者（WORKFLOW §7.2）。
- **REDESIGN**：方案根本不可行；审核者修改规格/任务卡（记 CHANGELOG），任务重新派发。

## 6. 审核者的额外职责

- 维护 `docs/tasks/STATUS.md` 与 `docs/plan/CHANGELOG.md`。
- 在派发依赖任务前，把前序任务中形成的、对后续有影响的约定补进后续任务卡（“来自前序的约定”一节）。
- 对标记为 **重点审核** 的任务（INDEX 中 ★）做独立数值验证：自己写小段脚本或测试重新计算关键量。
