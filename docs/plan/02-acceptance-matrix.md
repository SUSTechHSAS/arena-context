# 02 · 验收矩阵（Acceptance Matrix）

- 性质：本文是 AerraGen（Issue #1）的**统一验收清单**。每条指标给出：**测量方法（命令或公式）、阈值、样本范围、验证阶段、证据产物、性质**。
- 性质分两级：**硬闸门（GATE）** —— 不满足则里程碑不通过，须修复或经户主书面同意变更；**护栏（RAIL）** —— 合理性区间，违反时须在报告中给出实测值、分析与户主决策，不得为通过而默默调参（保留参考 §08.7 精神）。
- 分类：**A** 口径类（待户主决策后生效，见 `03-open-decisions.md`）/**B** 数值正确性（单元与集成测试）/**C** 真实性统计（mini 预设为主）/**D** 性能与资源（机器相对）/**E** 工程质量。
- **v3（第 2 轮 plan-review）修订**：AC-1 改写并新增 AC-1b；AC-2 的重力判据更正（R/r=4 时圆柱近似高估 19%，独立积分见 `docs/plan/analysis/`）；NX-06 拆分为 NX-06a/b/c；NX-18、NX-20 具体化（NX-20 拆分为 a–e，修复测量/阈值子项数目不一致）；新增 NX-29、NX-30、RS-17、PF-09、PF-10、QE-07–09 与 §02.G（证据留存）。**数值复核命令：`python3 docs/plan/analysis/verify_plan_numbers.py`（约 60 s，输出 `verify_output.txt`）。**
- **量化口径（全表适用）**：GB = 10⁹ 字节；内存为 `VmHWM`（2²⁰ 换算）；区间含端点；相对误差一律 `|实测−参考|/参考`；未注明预设时指 `mini`（GATE）或声明处所指预设。
- 证据统一格式：测试输出（`cargo test` 名称与结果）、`previews/metrics.json` + `metrics.md`、基准输出 `bench.json`、审查图 `artifacts/<Txx>/`、阶段报告（模板见 01 §7.2）。所有证据须可复现：记录命令、预设、seed、代码版本、机器。
- 总闸门：每个里程碑 M0–M8 的出口 = 对应行全部 GATE 通过 + 审查图 + 报告 + Kibiandkimi 人工批准（PR 审核）。

## 02.F 验收流程（每个里程碑）

1. 实现单元在 `work/1/<unit>` 完成开发，本地运行 `scripts/check.sh` + 对应慢速测试 + `terragen bench`（相关项）+ `terragen metrics`（相关项）。
2. 生成审查图到 `artifacts/<Txx>/` 并自行检查（NaN 空洞、条纹、接缝、块状伪影、异常对称、数值范围）。
3. 写阶段报告（模板见 01 §7.2）：实测值 vs 阈值逐行对应，偏差与未完成项诚实列出。
4. 更新 `.context/STATE.md`，提交（SUSTechHSAS），推送，开/更新 PR（base `AerraGen-main`），保持 Draft 直到可审核。
5. `arena/protocol` 检查通过（分支归属、交接文件、规则变更范围）。
6. Kibiandkimi 人工审核：复现（抽查数值，差异 > 5% 视为 MAJOR）、规格符合性逐条对照、图像审查、批准或返工（分级见 01 §7.2）。**批准后才进入下一里程碑；不得自动合并。**
7. 全部闸门通过后，由 Kibiandkimi 进行任务最终验收与收尾（此后才涉及 `.context/DEFERRED_TASK.txt`，之前严禁解码）。

## 02.G 证据留存政策（第 2 轮新增；细则见 `01 §1.8`）

1. **每个 GATE 项必须绑定一条可执行命令**（写入对应测试的 doc 注释或报告），并记录：预设、seed、代码版本、机器、耗时。无法给出命令的指标视为未定义，不得作为验收依据。
2. **随 PR 提交**：`docs/reports/M<k>.md` 阶段报告、`metrics.json`/`bench.json`/`diag.json`、`verify_output.txt`、单张 ≤ 5 MB 的审查图；更大的图/动画/世界目录**不入 git**，须提交 SHA256 + 生成命令 + 关键统计量。
3. **复现要求**：评审者应能在当前环境用文档中的命令重现每个 GATE 结论（时间预算：单项 ≤ 10 min，完整里程碑 ≤ 2 h；超出者须在 M0 建立"分档运行"说明）。当前沙箱缺 Rust 工具链（D8），因此**在 D8 解决前，QE/NX/PF 类证据一律标注"未运行"**，不得以计划值冒充实测值。
4. 未通过/未运行的项必须显式列出（`[未运行]`、`[失败]`、`[降级]`），不得省略。
