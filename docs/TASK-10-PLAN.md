## 拟采用技术方案（待批准）

1. **React + TypeScript + Vite**：主菜单、HUD、背包、设置、编辑器/工坊面板采用组件；地牢采用 Canvas 渲染以保留原有交互和大地图性能。
2. **独立 TypeScript 逻辑层**：世界状态、实体、回合、生成、物品/战斗、存档不依赖 React；明确命令输入及事件输出，UI 不决定游戏规则。
3. **可注入环境**：PRNG、时钟、计时器、存储、网络适配器。优先保留原 PRNG 算法及调用顺序，不能仅以“同种子”假定同结果。
4. **Vitest + Playwright**：逻辑单测/差分测试与浏览器端流程；锁定依赖版本，提供 `dev`、`typecheck`、`lint`、`test`、`test:e2e`、`build` 命令。
5. 原源码冻结为测试参照，保留校验和和来源；参照浏览器运行使用测试桥接而不是重写原规则。桥接修改与业务代码区分，公开其提取/注入方式。
6. 第三方字体、图标、动画等尽量本地依赖，保留许可；不得把旧 HTML/iframe 包装成“完整重写”。

- 识别实际存档/地图格式、输入入口、全局状态和 PRNG；建立原版启动 harness。
- 设计逻辑快照协议及允许忽略的非逻辑字段；忽略列表必须附理由，不能隐藏玩法状态、引用关系或随机数消费。
- 初始化工程、测试命令及最小启动界面；先迁移 PRNG/基础数据，演示一条端到端差分轨迹。
- 交付：审计矩阵、来源清单、架构文档、可运行参照 harness、基础工程、首批差分测试。未迁移功能显式标未完成。

### B. 基础游戏循环

迁移地图/房间/门/楼梯、路径与视线、移动/等待、回合顺序、视野、初始角色、楼层切换、基础 HUD。每个子单元连同差分测试提交，不先大量改写再补测试。

### C. 完整玩法

按注册表分批迁移所有怪物、物品、装备、Buff、职业、宠物、NPC、谜题、天气、特殊楼层/首领、教程和结局。每个实体测试正常路径与关键边界，覆盖组合效果和回合顺序。

### D. 存档、编辑器与附属入口

迁移原版存档/地图导入导出、编辑撤销重做、复制粘贴、属性编辑、自定义 NPC、Viewer、工坊、种子筛选与设置。读取旧数据不执行不可信脚本；如与原行为冲突，登记差异并提交审核。

### E. 外部集成及最终验收

隔离 Supabase/联机接口，先用契约 mock 测试成功/失败/空数据等；只有获得授权和可用环境才实测真实服务，不向旧生产服务写入或删除数据。完成全功能矩阵、跨浏览器/触控流程、构建与运行说明、性能基线和差异审查。
